# 🧪 Stewie Lab

> 把踩过的坑，写成实验报告。

“本地没问题，打包部署后却不显示。”这是实验登记簿里的一篇文章，也是我很熟悉的开场白。打开 Network 面板，重现一次，划掉几个猜测。等页面终于出来，再把真正起作用的那一步记下来。

Stewie Lab 是我的个人技术博客。踩坑报告有一册，平时做题和复盘也有一册。首页还摆着一台可以调频率的示波器。

**[进实验室逛逛 ↗](https://stewie.fun)**

## 实验登记簿里有什么？

### 技术文章

记录那些值得从头讲一遍的问题，比如一个页面部署后为什么不显示，或者同一张卡片放到侧栏后为什么被挤坏。想直接看原因，可以顺着目录跳过去。想亲手试试，代码块可以一键复制。

### 随手记

「今日八股」、技术练习和阶段复盘都放在这里。一页可能刚在捋 JVM 的并发标记，翻到下一页就聊起了长列表该怎么定位。每篇带着自己的日期和封面，按月份往回翻。

知道要找什么时，按 `Ctrl + K`（Mac 上是 `⌘ + K`）就能打开搜索。还没决定读哪一篇，可以在登记簿右侧看看热门文章和浏览量。

## 实验台上可以动手

- **拨一拨示波器。** 点屏幕换波形，展开「调节信号」调整频率和振幅。想看清某一帧，就按「冻结」。
- **把卡片挤一挤。** 在容器查询小实验里拖动滑杆，把卡片放进越来越窄的容器，再切换媒体查询和容器查询看看差别。
- **抽一篇旧文章。** 首页的「抽一个实验」会从已发布的记录里抽选，刚发布的文章和压在下面的旧记录都可能翻出来。

如果逛到「关于」，还能看到研究员的装备栏。至于桌上那颗表情球，碰一下就知道了。

## 在本地启动

前端用 **Vue 3、TypeScript、Vite、Vue Router、Pinia 和 Unhead**，示波器用 Canvas 绘制。文章、评论和后台数据由 [Spring Boot 后端](https://github.com/zssz666/stewie-blog-springboot) 提供，使用 MySQL 和 Redis。

先准备 Node.js（`^22.18.0` 或 `>=24.12.0`），再进入前端仓库根目录运行以下命令。

```bash
npm ci
npm run dev
```

查看文章、搜索或使用后台时，用 Java 17 启动配套后端。开发服务器会把 `/api` 和 `/uploads` 转发到 `http://localhost:8081`。Vite 会在终端显示前端访问地址。

| 命令 | 用途 |
| --- | --- |
| `npm run dev` | 启动前端开发服务 |
| `npm run type-check` | 检查 TypeScript 和 Vue 模板类型 |
| `npm run build` | 执行类型检查并构建到 `dist/` |
| `npm run preview` | 在本地查看构建结果 |

前后端同源部署时，由反向代理转发 `/api` 和 `/uploads`，并让页面路由回退到 `index.html`。跨域部署时，在构建前将 `VITE_API_BASE_URL` 设为后端的公开 API 基址，例如 `https://api.example.com/api`。

## 代码从哪儿看？

```text
src/
├── api/          # 文章、搜索、认证和互动接口
├── components/   # 文章卡片、随手记、搜索弹窗和实验台组件
├── composables/  # 可复用的交互与页面逻辑
├── editor/       # 编辑器区块构建
├── router/       # 页面路由和后台登录守卫
├── stores/       # 登录、主题和界面状态
└── views/
    └── admin/    # 后台布局、文章编辑与评论管理
```

登录后的后台入口是 `/admin`。写文章时可以切换 HTML 源码与实时预览、上传封面，再决定先存草稿还是发布。
